# Shadow of the Colossus PC — полный обзор проекта

Состояние на 12/10/2026 (ветка `sotc`, коммит `e5d6233` и последующие). Публичный репозиторий:
<https://github.com/AjncSystem/ShadowOfTheColossus-PC> (опубликованы версии 0.0.8 и 0.0.9).

Этот документ собирает в одном месте, что представляет собой проект, как он работает, всё, что
сделано на данный момент, показатели производительности, известные проблемы и дальнейшие шаги.

---

## 1. Что это такое

**Нативный порт для Windows** игры *Shadow of the Colossus* для PS4 (CUSA08809, EU, версия
исполняемого файла 1.01). Это не полноценный эмулятор, как shadPS4: код игры выполняется
**непосредственно на процессоре ПК**, а воссоздаётся только то, что присуще исключительно PS4:

| Компонент PS4 | Как это решает порт |
|---|---|
| CPU (AMD Jaguar, x86-64) | код игры выполняется **нативно** на x86-64 ПК (та же архитектура). При загрузке исправляются только немногие инструкции, которых нет у Intel (SSE4a), и использование *red zone*. |
| Операционная система (Orbis OS) | собственная среда выполнения (`src/runtime_*.c`) реализует системные функции, которые вызывает игра: память, файлы, потоки, сохранения, звук, контроллер, диалоги… |
| GPU (AMD GCN "Liverpool") | **эмулируется**: команды PM4 и шейдеры GCN игры транслируются в **Vulkan** (видеоядро shadPS4 с исправлениями из нашего форка). |
| Библиотеки игры (libc, Fios) | библиотеки из самого дампа компонуются нативно на этапе подготовки. |
| Звук (libSceNgs2 / libSceUlt) | компонуются модули **с собственной консоли пользователя** (никогда не распространяются). |

Основа: проект *bbport* (нативный порт Bloodborne, GPL-2.0), адаптированный под SotC.

## 2. Как это работает (ход выполнения)

1. **`SotC.exe`** (лаунчер, Python/Tkinter, упакованный с помощью PyInstaller): первоначальная
   настройка, библиотека игр, параметры изображения и управления, после чего он вызывает
   `sotc.py`.
2. **`sotc.py`**: подготавливает игру один раз (и повторно — только при каких-либо изменениях):
   - `scripts/prepare.py` преобразует `eboot.bin` (SELF) в плоский образ;
   - `link_modules.py` / `link_libc.py` компонуют libc, Fios и звуковые модули пользователя;
   - `content_profile.py`, `sotc_cpu.py` (исправления CPU), `sotc_modes.py` (60 FPS, AF 16x,
     cvars движка);
   - если есть обновление (`CUSA08809-UPDATE`/`-patch`) с `eboot.bin`, используется его образ.
3. **`bb-probe.exe`** («игра»): загрузчик на C (`src/probe.c`) + среда выполнения + видеоядро
   (`gpu/`). Загружает образ **ниже 2 ГиБ** (игра хранит указатели в 31 бите), создаёт потоки и
   файберы игры и запускает её.

### Каталоги

| Папка | Содержимое |
|---|---|
| `src/` | загрузчик и среда выполнения (память, файлы, сохранения, звук, геймпад, сервисы, файберы, SotC) |
| `gpu/shadps4/` | видеоядро (video_core, shader_recompiler, gnmdriver, videoout) |
| `gpu/shim/` | связующий слой между средой выполнения и видеоядром, окно SDL, оверлей ImGui |
| `gpu/sotc/` | исправления CPU (SSE4a, red zone), перенесённые из форка |
| `scripts/` | подготовка игры |
| `launcher/` | `SotC.exe` (sotc_launcher_win.py, sotc_discovery.py, значки) |
| `tools/` | автоматические тесты, бенчмарк, A/B, профилировщик |
| `packaging/windows/` | `package_sotc.sh` → `dist/SotC-PC.zip` (отклоняет `.sprx/.prx`) |
| `docs/sotc/` | этот документ, README пакета, план «пути B» |

## 3. Хронология

### 07/10 — игра запускается
- Импорты сопоставляются по NID; функции SotC вынесены в отдельный файл (`runtime_sotc.c`).
- Дополнительное окно памяти `0x700000000–0x800000000` (игра выполняет отображение по
  фиксированному адресу).
- Игра доходит до собственной инициализации.

### 08/10 — игра проходима
- **Файберы** (`runtime_fiber.c`), **исправления CPU** (SSE4a, red zone) и **образ ниже 2 ГиБ**
  → первые кадры (сокол в каньоне).
- Исправления GPU из форка применены к ядру bbport → вступление без чёрных полигонов.
- **Переломный момент:** видеоядро **нашего форка shadPS4** вместо видеоядра bbport → логотипы,
  меню с текстом, загрузка сохранения, открытый мир при 30 FPS, 10 минут без вылетов.
- Устранён тихий вылет: трекер страниц защищал стеки файберов.
- **Настоящий звук** с модулями пользователя; лаунчер `sotc.py`/`SotC.bat`; пакет для Windows.
- **Режимы**: AF 16x и 60 FPS (патч при загрузке, `BB_VBLANK_HZ=120`).
- `SotC.exe` (графический лаунчер), управление из bbport 0.4 (клавиатура и контроллер
  одновременно, переназначение), камера на мыши, выходное разрешение 720p–4K, режим PS4 Pro,
  эффекты движка.

### 08–09/10 — производительность
- Постоянный бенчмарк: **демо экрана заставки** (всегда один и тот же маршрут).
- Улучшения: кэш информации о шейдерах, HLE вычислительного прохода, заполняющего таблицы,
  кэш указателей памяти для каждого потока, cvars отсечения из Pink, защита кучи BPE,
  синхронизация буферов без блокировок, непрямые вызовы отрисовки с аргументами на CPU
  превращаются в прямые, запись команд Vulkan в отдельном потоке, кэши описаний и поиска
  изображений, меньше ошибок записи, периодическая отправка по времени (`SOTC_FLUSH_US=500`).
- Результат в демо (60 FPS, i9-13900K + RTX 2060 SUPER): **в среднем 37–45 → ~67 FPS**, самый
  тяжёлый участок (мост в каньоне) **~17 → 29–34 FPS**.

### 12/10 — лаунчер, публикация, сохранения, текстуры
- **Публичная 0.0.8**: библиотека игр, автоматический поиск, переназначение клавиш, новый
  значок, параметр отправки работы на GPU (AMD/Intel).
- **Публичная 0.0.9**: экран первоначальной настройки (запрашивает только основную папку, как
  shadPS4), обновление как в shadPS4 (`-UPDATE`/`-patch` поверх базовой игры), **DLC** в папке
  или **`.pkg` без установки** (6 DLC передаются игре).
- Проект собран в **единую папку** (`SotC-PC`).
- **Исправлено сохранение**: игра никогда не сохранялась («нет места»).
- **Потоковая загрузка текстур** (`GET_LOD_STATS`): чёткие текстуры вблизи, водопады с водяными
  завесами, рябь на поверхности воды.
- **Экранный список сохранений** для загрузки и сохранения, с **удалением сохранений**.

## 4. Текущие возможности

- **Лаунчер** (`SotC.exe`): настройка при первом запуске; находит игру, обновление, DLC,
  сохранения shadPS4 и звуковые модули; библиотека; параметры изображения (выходное
  разрешение, FSR 1, резкость, AF 16x, 60 FPS, PS4 Pro, эффекты), управление
  (клавиатура/контроллер/мышь, переназначение), отправка работы на GPU; ярлык на рабочем столе
  со значком игры.
- **Игра**: проходится от начала до конца в обычном режиме; настоящий звук; сохранения
  (сохранение, загрузка, удаление); DLC; обновление 1.01; режим PS4 Pro
  (Кинематографический/Производительность в меню игры).

## 5. Основные технические исправления

| Проблема | Причина | Исправление |
|---|---|---|
| Тихий вылет без сообщения | страница стека файбера защищалась трекером GPU | стеки файберов регистрируются и исключаются из отслеживания |
| Повреждённые указатели игры | игра хранит указатели в 31 бите | образ загружается ниже 2 ГиБ |
| Чёрные полигоны во вступлении | отсутствовали исправления GPU из форка | видеоядро форка |
| Периодический чёрный экран | оптимизации bbport несовместимы с SotC | ядро форка; точные чтения из GPU |
| Игра никогда не сохранялась | порт сообщал, что каждое сохранение занимает 1 ГиБ | реальный размер сохранений |
| Загрузка зацикливалась / каждое сохранение создавало новый слот | диалог списка «завершался» без выбора | список отрисовывается на экране (оверлей ImGui) |
| Размытые текстуры, чёрная вода, водопады без завес | команда `GET_LOD_STATS` игнорировалась → игра никогда не загружала детальные мипы | статистика эмулируется по используемым текстурам; текстуры загружаются повторно, когда игра отображает новую память |
| Очередь GPU зависала при записи в отдельном потоке | презентер ждал тик до его отправки | ожидание отправки перед показом кадра |

## 6. Известные проблемы (по приоритету)

1. **Повреждение памяти при потоковой загрузке текстур.** Запрос максимального разрешения
   (mip 0/1) для всего приводит к тому, что игра повреждает собственную память за 1–4 минуты;
   с текущим ограничением (mip 2, 512×512) демо проходит целиком, но **загрузка другого
   сохранения без перезапуска игры может её закрыть**. Рекомендация: перезапускайте игру перед
   сменой сохранения. Проверены и **исключены** как причина (12/10): ранняя запись меток EOP
   (`SOTC_EOP_DEFER=1` записывает их по завершении работы GPU: FPS падает вдвое, а сбой
   сохраняется), HLE-копирование, помечавшее весь диапазон как записанный GPU (исправлено на
   пометку только фрагментов; сбой сохраняется), и отказы среды выполнения в выделении памяти
   (их нет). Симптом всегда один: память, повторно использованная игрой, всё ещё читается или
   записывается устаревшими данными (узлы кучи, дескрипторы и шейдеры с мусором) примерно на
   250–270 с демо при mip 0/1.
2. **Чёрные тени**: затенённые области без фонового освещения (недавние изменения ситуацию не
   ухудшили). Зацепка (захват RenderDoc храма во вступлении, ~178 с): вход половинного
   разрешения проходов освещения (960×540, A2B10G10R10, читается ~16 отрисовками света)
   **никогда не записывается в кадре и остаётся нулевым** — вероятно, отсутствует фоновое
   затенение или непрямое освещение. Пока неизвестно, какой проход должен его записывать (не
   найдено ни записи как изображения, ни записи как буфера).
3. **Вода**: в некоторых местах озеро непрозрачное или гладкое; колыхание волн не подтверждено.
4. **Вылет в демо экрана заставки** через несколько минут (то же семейство, что и пункт 1).
5. Старые сохранения, скопированные из shadPS4, отображаются с меткой "Profile" (метка
   исправляется при перезаписи сохранения).
6. AMD/Intel: оптимизации отправки по умолчанию отключены и мало протестированы.

## 7. Диагностика (переменные окружения)

| Переменная | Назначение |
|---|---|
| `SOTC_FPS=1` | FPS и чтения из GPU в журнале каждые 5 с |
| `SOTC_SAVE_TRACE=1` | журналирует вызовы сохранения |
| `SOTC_LOD_STATS=0` / `SOTC_LOD_LEVEL=n` / `SOTC_LOD_TRACE=1` | потоковая загрузка текстур: отключение, запрашиваемый уровень, журналирование |
| `SOTC_MAP_INVALIDATE=0` | не загружать текстуры повторно, когда игра отображает память |
| `BB_WRITE_LOG=1` | журнал записей порта в память игры (выводится при сбое, с итогами по источникам) |
| `SOTC_RDOC_TRIGGER` + `SOTC_PLAY_WRAP` | захват RenderDoc одной отправки на GPU (`renderdoccmd capture`) |
| `SOTC_SHOT_OVERLAY=1` | снимки экрана с оверлеем (списком сохранений) |
| `BB_FRAME_DUMP_TRIGGER` | снимок кадра при появлении файла |
| `BB_PAD_FILE` / `BB_PAD_RECORD` / `BB_PAD_REPLAY` | контроллер из файла, запись/воспроизведение маршрута |
| `SOTC_PROFILE=<thread>` | выборочный профилировщик |
| `SOTC_FLUSH_US`, `SOTC_RB_AHEAD`, `SOTC_RECORD_THREAD`, `SOTC_INDIRECT_DIRECT`, `SOTC_FILL_HLE` | оптимизации (включение/отключение для тестов) |

Инструменты: `tools/sotc_play.py` (сценарий: `t:cross`, `t:shot`, `t:rdoc`…),
`tools/sotc_bench_attract.sh` (бенчмарк), `tools/sotc_intro_ab.sh` (A/B у реки во вступлении),
`tools/profile_sym.py`.

### О DirectX 12

Порт **уже является нативным x86-64 для Windows**: код игры выполняется непосредственно на
процессоре. Единственная «эмулируемая» часть — GPU, который сейчас транслируется в **Vulkan**.
Переход на DirectX 12 означал бы переписать всё видеоядро (тысячи файлов трансляции команд и
шейдеров GCN → SPIR-V) под D3D12/DXIL без реального выигрыша: Vulkan работает на всех
видеокартах под Windows (NVIDIA, AMD, Intel), а производительность зависит от трансляции, а не
от API. «Полная» обратная разработка (воссоздание рендерера игры на DirectX без трансляции GPU)
стала бы отдельным проектом длиной во много месяцев. Путь, который даёт результат, — продолжать
исправлять текущую трансляцию.
